# Facts about the RS3 Client Plugin API that runescape-api-stubs does not state, for Oneiro's bindings generator.
# Each line is "<fact> <target> [<argument> ...]", then "#" and how the fact was checked:
#
#   docs       the official documentation at developer.runescape.com/rs/ says so
#   stubs      the stubs' own descriptions say so, though their types do not
#   client     checked in the beta client, with the date
#   unchecked  inferred; to be checked in the client before anyone relies on it
#
# Targets are Lua names as the stubs declare them: a class (ui.Text, NPCEntity), a member (Player.GetEntity,
# NPCEntity.coordGrid), an event field (Event.ChatMessage) or a global function (require). The facts:
#
#   singleton <class>            a global table that is one object: its colon functions are static, with @LuaColon
#   instance <class>             a global table whose colon functions are methods of the objects its new makes
#   constructible <class>        the plugin builds tables of this type: a public constructor making {}
#   not-constructible <class>    the plugin never builds tables of this type
#   nullable <member>            the function or field can be nil, though the stubs' type says otherwise
#   not-nullable <member>        the function or field is never nil, though the stubs' type says it can be
#   read-only <class|field>      the field, or every field of the class, is read-only: final in Java
#   writable <field>             the field can be assigned, though the defaults would make it final
#   copied <class>               a field of this type, on an object the client hands out, gives a copy: an edit in
#                                place is lost, so Java rejects it
#   not-copied <field>           the field gives the client's own value, though its type is copied
#   java-name <class|member> <n> the Java name for a Lua name; the Lua keeps its own
#   rename <member> <name>       the client's name for a member the stubs misspell; Java and Lua both use it, and the
#                                other lines name the member by it
#   values <enum> <NAME=value...>  the values the client gives an enum's names, where the stubs give others
#   type <member> <type...>      the LuaCATS type of a field, or of what a function returns, where the stubs' is wrong
#   field <field> <type...>      a field the docs give and the stubs lack, with its LuaCATS type; for a class the
#                                stubs lack, its lines declare it, for a type line to use
#   function <Owner.Name> <fun>  a function the docs give and the stubs lack, or whose form they get wrong, as a
#                                fun(...) type; Owner:Name for a colon call; a further line adds another form
#   param <function> <name> <type...>  the LuaCATS type of a function's parameter, where the stubs' is wrong
#   superclass <class> <class>   the class the docs say it extends, where the stubs give none
#   hook <table.NAME> <Callback> <name:Type...>  the callback a hook takes, after the component it fired on: a
#                                functional interface; table.JAVA=LUA adds a second Java constant for one hook
#   operator <Class.name> <op> <fun>  one of Lua's operators on the class's objects, as a method: a.plus(b) is a + b
#   returns <function> <Record> <name...>   the record and component names of a function's several return values
#   permission <class|member> <p>  using it needs the manifest permission
#   manifest-flag <event> <flag> subscribing to the event needs the manifest flag
#   dev-only <member>            allowed only in a plugin's dev source set
#   skip <class|member>          not bound at all
#   element-table <class> <Type> <name...>  the stubs describe one element of the table as the table itself
#
# The generator warns about any line that names something the stubs do not have. A line the stubs have caught up with
# (they now say the same everywhere it applies, or no longer have the member a skip leaves out) changes nothing and is
# only noted in Oneiro's own tests as no longer needed, so a fix upstream needs no change here.

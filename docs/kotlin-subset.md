# Supported Kotlin

What Oneiro accepts in a plugin's Kotlin source and the Lua it produces. The Kotlin front end accepts what these
tables list; anything else fails with a message, either that it is not supported yet or, marked *Never* here, why Lua
cannot follow it and what to write instead. How a plugin is built, packaged and linked into the client is in
[plugin-model.md](plugin-model.md).

The same two rules decide every row as for Java ([java-subset.md](java-subset.md)): the ordinary Kotlin form is
accepted wherever a faithful, readable Lua translation exists, and only genuine gaps between Kotlin and Lua are
rejected, with an error that says why and what to write instead. Each row has a test: most a Kotlin twin of a Java
conformance case, which must give the same Lua, and the rest cases of Kotlin's own, whose names start with `kotlin-`.

## Files and modules

| Kotlin | Lua | Notes |
| --- | --- | --- |
| A file that declares one `object Row` | `src/core/row.lua`: `local Row = {}`, its functions, and `return Row` | The packages below the plugin's root package become folders under `src/`, and the declaration's name, in snake case, the file's name. |
| A file that declares one `class Tally` | `local Tally = {}` and `Tally.__index = Tally`, `Tally.new()`, its methods, and `return Tally` | As a Java class with instances. |
| `enum class Mode { COUNT, LIST }` | `local Mode = { COUNT = "COUNT", LIST = "LIST" }` | A simple enum: each constant is its own name. A comment after a constant goes above it. |
| `enum class Herb(val seedId: Int) { GUAM(5291), ... }` | `local Herb = {}`, `Herb.new(name, ordinal, ...)`, and `Herb.GUAM = Herb.new("GUAM", 0, 5291)` | An object enum: its constants are objects, with `name` and `ordinal`, when the enum has a constructor, properties, functions or constant bodies, or when code reads their order, through `ordinal`, `compareTo`, `<`, a sort in natural order, or a key a sort or comparator orders by. A constant's body sets its own members, `Herb.RANARR.note = ...`. `Herb.__lt` orders the constants as they are declared. |
| A class, object or enum inside another | `local Tab = {}`, with `Bank.Tab = Tab` unless it is private | Its table and members come before those of the class around it. |
| The declaration's KDoc | The header comment, after a first line with the file's path | Comments above the declaration come first. Without KDoc there is a warning, because every Lua file needs a header. |
| Using a class of another file, `Tally()` | `local Tally = require("src/tally")` at the top, and `Tally.new()` | |
| A translation that needs a helper, such as `map.size` | `local tableLength = require("utils/table_length").tableLength` at the top, after the modules the file requires, and `tableLength(map)` | Each helper is a file of its own under `utils/`, which the plugin ships when its code uses it, as for Java; see [Helpers](java-subset.md#helpers). |
| A local the Lua needs that the source does not have, such as a chain's list or `pcall`'s `ok` | A name for what it holds: `count`, `first`, `parts`, `ok` | Each name is taken once in a function, so that none hides another: one the source has, or another made-up local has, takes a number from 2, `count2`. A list, a set or a map is named after the parameter of the plugin's or the client's function it is handed to, `texts` for `show(section, texts)`, or after the property it becomes, `lines` for `lines = buildList { ... }` or `lines[section] = ...`, where that name is free, and otherwise after its kind, `list`. A loop's variables, `key` and `value`, are free again after the loop. |
| A function's KDoc | Its description as comment lines, then `---@param row integer[]? text` and `---@return boolean complete text` | As in Javadoc, a return text that starts with a name and a colon, `@return complete: text`, names the return value. |
| Code that runs while the module loads, `val SQUARES = build(4)` and an object's `init` block | After the functions it calls | A local used above its definition is declared ahead. A `const val` uses nothing and goes first, where Lua authors put constants. |
| A file that declares two classes, objects or interfaces | *Never*: "Lua has one module per file; move Second into a file of its own." | |
| A file of top-level functions and properties, `Levels.kt` | `src/levels.lua`: `local Levels = {}`, `Levels.MAX_LEVEL = 99`, `function Levels.clampLevel(level)`, and `return Levels` | The module is named after the file, and lowered as an object is: private functions and properties are locals. Its header is the comment above its package line. Another file requires it, `local Levels = require("src/levels")`, and `clampLevel(it)` there is `Levels.clampLevel(it)`; an extension function takes its receiver first, `Levels.levelText(self)`. The dev source set calls the main set's the same way, `Levels.clampLevel(it)` with `local Levels = require("src/levels")`. |
| `typealias Level = Int` | Nothing | A file of type aliases alone has no Lua. |
| A private top-level function or property in a file with a class, `private fun tidy(name: String)` | A local of the class's module, `local function tidy(name)` | In the plugin class's file, top-level properties are locals of `main.lua` whatever their visibility. Any other top-level function or property beside a class is *Never*: "Lua has one module per file, and this file's is Stray's, so a top-level function that other files use has no module to go in; make it private, or move it into Stray or a file of top-level functions and properties of its own." Beside a data class of properties alone, which has no Lua of its own, every one is *Never*. |
| Two files whose Lua would be one file, such as `Twin.kt` of top-level functions and an `object Twin` | *Never*: "The Lua of this file would be src/twin.lua, which Twin.kt makes too; rename one of them." | |
| A name that is not ASCII letters, digits and underscores, `fun größe()` or `` fun `my name`() `` | *Never*: "Lua names are ASCII letters, digits and underscores only; rename größe." | The rest of the file is not checked until the name is renamed. |

## Classes and objects

| Kotlin | Lua | Notes |
| --- | --- | --- |
| `fun complete(row: List<Int?>?): Boolean` in an object | `function Row.complete(row)` | A private function is a local, `local function complete(row)`. |
| `class Tally(var label: String)` | `function Tally.new(label)`, which sets `self.label = label` | |
| `constructor(name: String) : this(name, 0)` beside `class Tally(val name: String, var total: Int)` | `function Tally.new(name, total)`, which starts `total = total or 0`; `Tally("herbs")` is `Tally.new("herbs")` | A secondary constructor that passes its parameters on, in order, with values for the rest, gives the primary constructor's parameters those values as defaults. Two that give one parameter different values are *Never*: "Lua gives a parameter a call leaves out one default, but total would take 0 and 1; give the constructors one value for it." A secondary constructor that does anything else is not supported yet. |
| `class Counter { var count: Int; constructor(start: Int) { count = start * 2 } }` | `function Counter.new(start)`, which runs the properties' values and the `init` blocks, then the constructor's code, `self.count = start * 2` | A class without a primary constructor, and one secondary constructor; its call to the superclass's, `: super(...)`, makes the object first. |
| `private var total = 0` in a class | `self.total = 0` in `Tally.new()` | Each property gets its value in declaration order, with the `init` blocks among them. In an `init` block, a constructor property's name is its parameter, as in Kotlin. |
| `fun add(amount: Int)` in a class | `function Tally:add(amount)` | Its properties are `self.total`, and a call of another method is `self:sum()`. A private method is a local that takes the object first, `bump(self)`. |
| `fun sum(): Int = total` | `function Tally:sum() return self.total end` | An expression body is the function's `return`. |
| `companion object { const val START = 0 }` | `Tally.START = 0` | A companion object's members are the class table's own. A private companion object's members only the class reaches, so they are locals: `local SIZE = 3`. |
| `inner class Tab(...)` | `Tab.new(outer, ...)`, which keeps `self.outer` | The outer object's members are `self.outer.owner`, and `this@Bank` is `self.outer`. |
| `open class Counters` and `class Boosted : Counters()` | `local Boosted = setmetatable({}, { __index = Counters })`, and `setmetatable(Counters.new(), Boosted)` in `Boosted.new()` | `super.level()` is `Counters.level(self)`. An abstract function has no Lua; its subclasses give the code. |
| `fun add(amount: Int = STEP, negative: Boolean = false)` | `function Overloads:add(amount, negative)`, which starts `amount = amount or STEP`, and for a `Boolean` `if negative == nil then negative = false end` | A call that leaves out an argument before one it gives passes nil. Lua cannot tell a null argument from a left-out one, so a parameter that may be null takes no default but null. The constructor's parameters take defaults too, and the class's KDoc `@param` and `@property` tags give their annotations. |
| An interface of abstract functions alone, `interface Measured { fun area(): Double }` | Nothing; it is a type | Its values are objects of the classes that implement it, `shape:area()`. |
| An interface with default functions, `interface Describable { fun describe(): String = ... }` | `local Describable = {}` with the default functions, which take `self` | A class that implements it gets each default it does not override: `Herbal.describe = Describable.describe`. The interface's companion object's members are its table's. |
| `class Herbal : Comparable<Herbal>` | `function Herbal.__lt(a, b) return a:compareTo(b) < 0 end` | So that `<` and `table.sort` order the objects as Kotlin's natural order does. |
| A class that implements a function type, `(Herb) -> Unit`, a Java functional interface such as `Runnable`, or a fun interface of the plugin's | `function Planter:__call(...) return self:invoke(...) end` | Its objects are called as the functions the library, or the fun interface's other values, are. |
| An object called as a function, `doubler(value)`, `Doubler()(value)` or `machine.doubler(value)`, whose class implements a function type or has an `operator fun invoke` | `doubler:invoke(value)`, `Doubler.new():invoke(value)`, `machine.doubler:invoke(value)` | Its `invoke`, called on the object, as Kotlin calls it. An object declaration's is `Lower.invoke(value)`; a value of a function type, an object expression that is a function, or a fun interface's value, is the function itself, `machine.callback(value)`. An `invoke` declared as an extension is not supported yet. |
| A data class with members, `data class Tile(val x: Int, ...) { fun stepsTo(...) }` | A class whose fields are its properties, `Tile.new(x, y, plane)` | The `copy()`, `componentN()`, `equals`, `hashCode` and `toString` Kotlin generates are *Never*: its Lua table has no such functions. |
| A data class of properties alone, `data class Summary(val seen: Int, val level: Int)` | A plain Lua table, built where it is constructed: `{ seen = seen, level = level }` | The class itself produces no Lua, so it also describes tables that Lua code passes in. |
| `==` on a data class or a class that declares `equals`, on either side | *Never*: "Kotlin's == compares these objects by equals, but Lua's compares tables by identity; compare their properties instead, or use === for identity." | `===` is Lua's `==`. A comparison with `null`, `saved != null`, is the same in both, `saved ~= nil`. |
| `fun interface Check { fun test(value: Int): Boolean }` | Nothing; its values are Lua functions | `check.test(value)` is `check(value)`. A class that implements it is called as the function too, through `__call`. Its default functions have no Lua function to be called on, so `check.describe()` is *Never*: "A value of Check is a Lua function, which carries no methods; make describe() a function outside the interface that takes the Check." |
| `Check { it > 0 }`, `Runnable { counts[0]++ }`, `Predicate<Int> { it < 10 }` | The lambda's function | A functional interface's value made of a lambda is the function itself; `predicate.test(value)` is `predicate(value)`. |
| `object : Shape("square") { override fun area() = 1.0 }` | A helper `withMembers(Shape.new("square"), { area = function(self) ... end })` | An object expression is a table of its properties and functions, each function taking `self`; with a superclass of the plugin's, those members go onto a new object of it. One that implements a function type, a fun interface or a Java functional interface is a Lua function. |
| `class Count(val word: String)` inside a function | `local Count = {}` and `Count.__index = Count`, then its members, inside the function | A local class: its functions are the class's, and it may not have private functions or classes of its own. |
| `fun total(vararg numbers: Int)` | `function Grids.total(...)`, which starts `local numbers = { ... }` | Only the last parameter can take any number of values. `total(*more)` passes `table.unpack(more)`. |
| `fun String.shout(): String = uppercase() + "!"` in an object | `function Texts.shout(self)`, and a call `name.shout()` is `Texts.shout(name)` | An extension function takes its receiver first, as `self`, which its `this` stands for; a private one is a local, `local function shout(self)`. The receiver's members can go unnamed, the Kotlin library's too: `add(amount)` is `self:add(amount)`, `uppercase()` is `self:upper()`, and `filter { ... }` starts a chain on the receiver. Only `toString()` and `format(...)` take `this.`, as they read the receiver as written. An extension function inside a class with objects is not supported yet. |
| `val String.initial: String get() = take(1)` in an object or a file | `function Texts.initial(self) return self:sub(1, 1) end`, and `name.initial` is `Texts.initial(name)` | An extension property is its getter, a function that takes the receiver first, as an extension function does; a private one is a local function. Its setter, and one inside a class with objects, are not supported yet. |
| `@LuaName("Ingest") fun ingest(...)` | `function Tracker:Ingest(...)`; every call is `tracker:Ingest(...)` | Keeps a name that existing Lua code calls. |
| `Levels.fromPenalty(penalty)`, of the class generated from `src/main/lua/core/levels.lua`, or `zyklib.objects.getOrElseUpdate(counts, "starts") { 0 }`, of a vendored library's | `local Levels = require("src/core/levels")`, then `Levels.fromPenalty(penalty)` | The plugin's own Lua and its libraries, as in [java-subset.md](java-subset.md#calling-existing-lua), with where their types come from in [using-lua.md](using-lua.md). The several values a function's `---@return` tags name are a Java record, whose components are read with calls, `summary.count()`, and which cannot be destructured. |
| `prettyui.version` and `prettyui.isLoaded()`, of a library plugin's class | `prettyui.version`; `if prettyui then` in a condition, `prettyui ~= nil` elsewhere | As in [java-subset.md](java-subset.md#calling-existing-lua), with the same rule on an optional dependency: a use of its global compiles only where a check reaches it in the same function, through `if` and `when` alike, and a lambda stops the search. |
| `prettyui::isLoaded` | *Never*: "isLoaded() checks the dependency's global, which is no function of the library's; write the reference as a lambda, { prettyui.isLoaded() }, which checks it when it is called." | |
| Two functions of one name in a class, object or file, `fun sum(a: Int, b: Int)` and `fun sum(a: Int, b: Int, c: Int)` | *Never*: "Lua functions have no parameter types, so two functions cannot share a name; rename one (for example sumAll, sumOne), or give one function default values for the parameters the others leave out." | |
| A property and a function of one name, `private var count` and `fun count()` | *Never*: "The property count and the function count() would share one slot in the Lua table; rename one." | A private function is a local, and shares no slot. |
| Two private members, or nested classes, of one name in the classes of a file | *Never*: "In Lua, the private members and nested classes of the classes in a file are locals of one scope, so two of them cannot both be named helper; rename one." | |
| `class Names : ArrayList<String>()` | *Never*: "Lua has none of ArrayList's code to inherit; keep one in a property instead of extending it." | |
| `class Mine : NPCEntity()`, a class that extends a binding | *Never*: "NPCEntity stands for Lua that Oneiro does not write, which a class of the plugin's cannot extend." | |
| `class Basket : Iterable<String>` | *Never*: "Lua's for loop walks tables, not iterator objects; give the class a function that returns its list, and loop over that." | |
| A class or member of the plugin's annotated `@LuaModule`, `@LuaGlobal` or another annotation of the generated bindings | *Never*: "@LuaModule belongs to the bindings Oneiro generates, not to the plugin's own classes; keep the Lua the plugin calls under src/main/lua, with LuaCATS annotations such as ---@param and ---@return, and call the class Oneiro generates from them." | The annotations are those [java-subset.md](java-subset.md#calling-existing-lua) lists. |
| `external fun outside(): Int`, or a property with `external get` | *Never*: "An external function would stand for Lua that exists already, which Oneiro binds from its annotations rather than from a declaration; keep the Lua the plugin calls under src/main/lua, with LuaCATS annotations such as ---@param and ---@return, and call the class Oneiro generates from them." | For an accessor: "An external accessor would stand for ...". |
| A class whose Lua would be a file of the plugin's own Lua, or classes of one name from two packages used in one file | *Never*: "The Lua of Tally would be src/tally.lua, a file the plugin's own Lua has already; rename the class or that file." and "In Lua, this file would require src/core/levels and src/ui/levels as one local, Levels; rename the class or file of one." | |

## The plugin class and settings

| Kotlin | Lua | Notes |
| --- | --- | --- |
| `class HerbPlugin : Plugin()` | `main.lua`, with no module table | Its properties and functions, whatever their visibility, are locals of `main.lua`. Only one class extends `Plugin`, in the main source set. |
| `class Cheats : DevPlugin()` in the dev source set | `dev/main.lua`, which never ships | Its `PluginShutdown` runs the plugin's own first. |
| `private const val REPORT_EVERY = 100` in the plugin class's file | `local REPORT_EVERY = 100` at the top of `main.lua` | |
| `override fun startUp()` | Its statements, after every member is defined | They run once, when the client loads the file. |
| `@Subscribe fun onServerLogic(tick: ServerLogicEventPayload)` | `local function onServerLogic()`, and `Event.ServerLogic.Subscribe("<id>.onServerLogic", onServerLogic)` after the `startUp()` statements | The parameter's type names the event. An event that passes nothing has an empty payload class, and its function takes no parameter. `EntityDraw`'s function returns a `Boolean`. |
| `override fun shutDown()` | The global `PluginShutdown`, which unsubscribes every `@Subscribe` function and then runs the body | |
| `@ConfigGroup("herbs") interface HerbConfig` | `src/herb_config.lua`: one function per setting, over `PersistentDB` | Each setting is kept under `"<group>.<keyName>"`. |
| `@ConfigItem(keyName = "greet", name = "Greeting") fun greet(): Boolean = true` | `function HerbConfig.greet()`, which returns the stored value, or the default when nothing is stored | A setting is a `Boolean`, an `Int` or `Long`, a `Double`, a `String`, or an enum of the plugin's, kept by its constant's name. |
| `@ConfigItem(...) fun setRuns(runs: Int)` | `function HerbConfig.setRuns(runs)`, which calls the typed setter | A setter has one parameter and no body. |
| `private lateinit var settings: HerbConfig` and `settings.greet()` | `HerbConfig.greet()` | The property holds nothing: every call through it calls the settings module. |
| `private var settings: HerbConfig? = null`, or `settings = null` | *Never*: "A property of settings needs no value: every call through it calls the settings module, so remove the initializer." | |
| `init { ... }` or a secondary constructor in the plugin class | *Never*: "The client creates the plugin class, and main.lua runs once; put start-up code in startUp() instead of an init block." | |
| `startUp()` or `shutDown()` called by the plugin's own code | *Never*: "startUp() runs once, when the plugin starts; move what it shares into a function of its own and call that." | |
| `HerbPlugin()` anywhere, `remember(this)` in the plugin class | *Never*: the client creates the plugin class once, and `main.lua` has no object to pass around | Use its members directly. |
| `@Subscribe` on a function of another class | *Never*: "Only the plugin class's functions are subscribed with @Subscribe; subscribe this one with Event.<Name>.Subscribe(name, callback), and unsubscribe it when it is done." | |
| `@ConfigGroup` on a class or an object | *Never*: "@ConfigGroup marks an interface of settings; make NotAnInterface an interface whose functions carry @ConfigItem." | |

## Statements

| Kotlin | Lua | Notes |
| --- | --- | --- |
| `val id = row[slot]` | `local id = row[slot]` | A local named like a Lua keyword or a global that the module uses gets a trailing underscore: `end_`, `table_`. So does one named like a local of the file that the same function uses, such as a private function, a property of an object or a member of the plugin class, which it would hide: `local step_ = n - 1` in a private function `step`. A local the Lua needs and the Kotlin does not have, such as a chain's `sum`, takes a number instead where its name would hide one: `sum2` beside a private function `sum`, or beside any name the function declares, in its own code or a lambda's. |
| `val ground = World.GetGroundHeight(0, x, z)`, of a type annotated `@LuaReturnValues` | `local height, available = World.GetGroundHeight(0, x, z)` | The several values a Lua function returns: each component the code reads, `ground.height()`, is a local of its own, named after the component, or after the local and the component, `eastHeight`, where the function has that name already. `val (low, high) = span(values)` destructures them, and a function of the type returns them, `return Span(low, high)` as `return low, high`. The local exists only as its components: passing it on is *Never*, and so is a parameter of the type. |
| `val (name, level) = entry`, `val (item, count) = drop`, `val (first, second) = names`, `val (_, level) = entry` | `local name, level = entry.first, entry.second`, `local item, count = drop.item, drop.count`, `local first, second = names[1], names[2]`, `local level = entry.second` | A pair's parts are `first`, `second` and `third`, a data class's its properties in the order its constructor takes them, and a list's its first elements. A part named `_` is not read. A pair made in place gives its parts directly, `val (first, second) = high to low` being `local first, second = high, low`; any other value that is not a name or a property read goes into a local of its own first, named after its type: `local pair = Pairs.ordered(a, b)`, then `local low, high = pair.first, pair.second`. |
| `val found = firstWith(names, "B") ?: return 0` | `local found = ...` and `if found == nil then return 0 end` | |
| `if (row == null) { return false }` | `if row == nil then return false end` | |
| `when (mode) { Mode.FAST -> ...; Mode.SAFE, Mode.OFF -> ...; else -> ... }` | `if mode == Mode.FAST then ... elseif mode == Mode.SAFE or mode == Mode.OFF then ... else ... end` | A subject with a call, or one Lua computes that more than one condition compares, is read once into a local named after it: `local size = #values`. `in 1..5`, `in list`, `is Boss` and a guard, `is Monster if level > 100`, are conditions too. An `else -> {}`, which a `when` over some of an enum's constants needs, leaves no `else`; one with a comment keeps it, as the `else`'s content. |
| `return when (...) { ... }`, `val x = if (...) { ... } else { ... }` | Each branch returns, or assigns the local | An `if` of single values whose first value is never false or nil, so that Lua's `and` gives it, stays an expression: `local sign = n < 0 and "negative" or "positive"`. |
| `log("The monster is " + when (mood) { ... })`, `describe(level, if (level > 99) { ... } else { ... })` | A local before the statement, which each branch assigns, `local value` or `local note`, then the statement with the local in its place | The local is named after the parameter it is passed to, or after its type, `text` for a string and `label` for a `Label`, or `value`; a second of the same name in the same statement takes a number, `text2`. A chain of collection functions, a `run { ... }`, a `buildList { ... }` and its kin, a `buildString { ... }`, a scope function whose code is more than one value, and a `takeIf` that needs a local of its own run before the statement the same way; a chain's local is named after its result, `any`, `count` or `sum`, and a `buildString`'s pieces are joined where its text is read, `log(table.concat(text))`. An `if` with such a value in a branch is statements of its own. Only where nothing would see the difference: the statement must run it every time, not only when a `?:`, a `?.` or a branch gets to it, nor each turn of a loop's condition or each time a lambda runs, and nothing the statement evaluates before it may call a function, other than one inside a value that runs before the statement too. Elsewhere it is *Never*, and the message says why: "In Lua this when is a statement, which can run before the code around it only where nothing would see the difference, but it comes after mood.toString(), which would then run later; give its value to a local of its own first, val x = when ..." |
| `wanted != null && drops.any { it.item == wanted }`, `!asked \|\| drops.all { ... }` | `local both = wanted ~= nil`, then `if both then` the chain's loop and `both = any end`; for `\|\|`, `local either = not asked` and `if not either then ... end` | When the right side of `&&` or `\|\|` needs statements, the whole test goes into a local first, and the right side's statements run only where Kotlin's right side would. The local is hoisted itself, as above. |
| `for (slot in 0 until 5)` | `for slot = 1, 5 do` when `slot` only indexes lists, in the body; otherwise `for slot = 0, 4 do` | As in Java, a loop counts from 1 when its variable is used only as an index, in `slot + 1`, or compared with another loop variable that counts from 1. |
| `for (name in names)`, over a list or an array | `for _, name in ipairs(names) do` | |
| `for (sprite in set)`, `for ((key, value) in map)`, `for (entry in map)` | `for sprite in pairs(set) do`, `for key, value in pairs(map) do` | `map.keys` and `map.values` are loops over the map with one variable. Lua has no entry of its own: an entry that is not destructured is read as `entry.key` and `entry.value`, the loop's two variables. A key the body never reads is `_`, and a value it never reads is left out, `for key in pairs(map) do`. |
| `for ((name, level) in entries)`, `for ((item, count) in drops)`, over a list, an array or a set | `for _, pair in ipairs(entries) do`, whose body starts `local name, level = pair.first, pair.second` | The loop's variable is named after the elements' type, and its parts are read as a destructuring declaration reads them. |
| `for ((index, name) in names.withIndex())`, `names.forEachIndexed { index, name -> ... }` | `for index, name in ipairs(names) do` when the position counts from 1, as for a loop over a range; otherwise `for i, name in ipairs(names) do`, whose body starts `local index = i - 1` | Over a list or an array. Kotlin counts the position from 0. |
| `for (i in from downTo 1)`, `for (i in 0..limit step 2)`, `for (i in values.indices)` | `for i = from, 1, -1 do`, `for i = 0, limit, 2 do`, `for i = 1, #values do` or `for i = 0, #values - 1 do` | |
| `for (c in text)` | `for c in text:gmatch(".") do` | |
| `while (n > 1) { ... }`, `do { ... } while (value > 0)` | `while n > 1 do ... end`, `repeat ... until not (value > 0)` | |
| `break`, `continue` | `break`, and `goto continue` to a label at the end of the loop's body | The label is `continue2` and up inside a loop that has one already. ## Collection functions

A chain of Kotlin's collection functions on a list, a set, an array, a range, a map, or a map's `keys`, `values` or
`entries` becomes one Lua loop, as the Java front end makes one of a stream: steps such as `filter`, `map`, `flatMap`,
`distinct` and `take`, then the call that gives the result, built up in a local. What the steps keep, such as a table
of the elements seen, goes into locals before the result's. Each lambda's parameter stands for the loop's
current element, so the lambdas' code reads as written; the first one names the loop's variable. A lambda of several
statements runs them in the loop's body, before what reads its value, its last expression; a value inside it that needs
statements of its own, such as another chain, runs them there too. A lambda's `return@map` is *Never*, as its code
runs in place: "Lua runs this lambda's code as the body of a loop, which return@map cannot leave; write the loop as a
for loop, and use continue." `flatMap`'s lambda is one expression. Kotlin runs each step
over the whole collection before the next, and the loop runs every step on one element before the next element, which
differs only for lambdas whose side effects depend on that order. A loop is statements: a chain that is the whole value
of a local, an assignment or a return builds its result there, and a `forEach` is a statement of its own. Inside
another expression, such as a condition, `count { ... } + 1` or the right side of `&&`, its loop runs before the
statement and builds the result in a local, as an `if` inside an expression does (see [Statements](#statements));
where that would change what the code does, it is *Never*, and the message says why: "In Lua a chain of collection
functions is a loop, which can run before the code around it only where nothing would see the difference, but it runs
only when the ?: gets to it; give its value to a local of its own first, val x = ..."
